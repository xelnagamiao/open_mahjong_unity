# 贵州 MIL 2023 的线上时间合同

建房默认是每人每局 20 秒额外思考局时、每次操作 5 秒步时。实际房间的 `round_timer` / `step_timer` 贯穿请求校验、保存和初始化，零局时也有效。不存在独立的 3 秒报听、碰杠或和牌上限。

`normal_claim_clock`：普通碰、杠、和牌及抢杠询问使用实际步时与剩余局时；即使开启战术鸣牌，首次询问也不缩短。`tactical_recheck_clock`：实际有效低优先级申请仍有高优先级竞争者时，复用公共战鸣优先级引擎并进入独立默认 5 秒再询问，步时为 0、普通局时暂停、不扣局时。贵州收集器从各自送达时刻起算，重连不重置。VII.4 允许场况变化后的更高优先级改报，因此不启用国标承诺锁；碰、杠同优先级不能互改。VIII.3 一炮多响和 VIII.6 强制和均保留。纯真人新房默认开启、可手动关闭，旧 false 保持；实际入座机器人在房间同步和状态初始化时强制关闭，空位/观战者不触发且移除机器人不自动重开。`claim_protection` 仍固定关闭。已阅读本轮最新计时引导及 2026-10-06 战鸣开发授权。

`ActionClock` 先耗步时，再耗该玩家本局剩余局时。内部保留小数；通用 `remaining_time` / `step_remaining` 只为整数协议向上取整。贵州 `guizhou_info.action_clock` 另携同一询问编号的精确局时与步时，供客户端保持截止点准确。

计时在本人询问走完出站 FIFO、完成 websocket 发送后开始，先于观战转发；其他视角的发送不移动这个起点。有效请求按进入 `submit_action` 的接收时刻冻结时钟，通过校验后入队，验证和消费者延迟不计入玩家思考时间。超时手动请求拒绝，自动响应只执行一次。重连、过期请求补发与实时观战快照只投影原窗口，发送前刷新，不再次启动或扣费；已接收响应不再询问。

开局闲家报听、普通摸打、自摸选择、碰杠和牌与抢杠询问都采用该合同。报听选择及取消携带同一个时钟，期间已耗步时不返还；服务器等待发送新选择界面的期间暂停。真正出牌、碰后出牌和杠后补张建立新窗口，只增加房间步时，沿用剩余局时。暗杠提交后的无人响应处理不建立时钟。贵州无吃牌、无花牌，因此没有吃牌或补花响应分支。

可选响应超时过牌；出牌超时选择当前合法牌，报听后只能摸切；规则强制和的抢杠/热炮窗口仍自动和牌。局终确认使用原结算时限，不扣牌局局时。开始下一局时每名玩家的局时恢复为房间配置值，包含庄家轮转后的身份。

回归入口：`test_timing_contract.py`、`test_clock.py`、`test_lifecycle.py`。可控时钟测试把步时内/超步时、接收/消费时刻、独立送达/整批发送、已完成/未完成响应、旧窗口/新窗口以及零局时区分验证；不通过修改秒数常量证明正确。
