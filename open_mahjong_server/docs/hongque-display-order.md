# 虹雀色环显示与牌谱升级

依据客户端所附《虹雀 v1.6》10 页规则：花色等级构成 14 位色环；刻组支持等级差 1、2，顺组支持等级差 0、1、2 及数字公差 1–4；亮出的组可继续扩展。

## 显示约定

- 鸣牌按合法组的连续花色与数字方向排列，比较两个方向后使用字典序较小者。`AX5 GX5 GY5` 显示为 `AX5 GY5 GX5`（红、红紫、紫）。完整色环也使用固定起点。
- 自动理牌在最大的空缺花色区间切开色环，使跨红紫边界的牌相邻。若原表格切口同样合适，保留它；同色数字升序。整手恰好构成合法组时，使用组内顺序。
- 对整手先算固定排名，再排序。不能直接对两个花色做环形比较，否则比较关系不满足传递性。
- 手动理牌顺序、独立摸牌位和弃牌时间顺序不参与上述重排。显示转换返回副本；规则判断、协议 ID、计分不变。
- Unity 的候选牌、三维鸣牌、自动手牌、牌谱展开、结算和计分记录共用这一约定；网页算番器和牌理器使用相同算法。

## 当前牌谱格式

虹雀杠牌 tick 现在必须带本家目标副露索引（从 0 开始）：

```json
["jg", 1015, "F", 0]
```

这表示把 `AY5` 加入第 0 组，与是否最后一组无关。扩展后整组重新确定显示顺序，全部竖置。两条 Unity 回放路径与计分记录提取均读取明确索引。

吃碰 tick 从第 3 个索引起都是本家投入的牌，允许多于两张，不能套用普通麻将的固定长度读取。

## 旧牌谱处理边界

一次性文件修复工具及其专用测试已移出常规源码，可恢复原件保存在本机 Git 忽略的 `.om_workspace/`。移出工具不代表所有外部旧牌谱已经处理，也不会改写数据库或自动安装兼容分支。

旧三项 `jg` 只有一个合法扩展目标时才能可靠补齐索引；有多个合法目标、原组非法、记录残缺或未知动作时必须保留原件并人工核对，不能猜测“最后一组”。若仍需修复旧导出文件，应在独立副本中恢复归档工具，先预检、备份并审核结果，不能直接覆盖唯一数据副本。

服务端新写入格式和客户端新读取器应一同发布；未处理的旧数据库牌谱须另行导出、修复并审核后再导回，不能仅升级读取器。

## 回归入口

- 服务端：`.venv/Scripts/python.exe -m pytest server/gamestate/game_hongque -q`
- 网页（`open_mahjong_web/client`）：`node --test tests/hongqueDisplayOrder.test.js tests/hongqueCalc.test.js`
- Unity Pipeline：主线程执行 `HongqueReplayLayoutValidation.Run()` 和 `MeldStackValidation.Run()`。
- Unity 穷举：`HongqueDisplayOrderValidation.Run(false)` 是纯数据检查，可从 Pipeline 派发后台任务。它覆盖全部 4,787 种合法组及 16,383 种非空花色集合；默认 `Run()` 还验证普通麻将排序，需在主线程运行。

验证包括花色/数字连续性、无丢牌或重复、输入不变、重复排序稳定、来源标记跟随牌、长鸣牌完整读取、扩展非末组、手动顺序、独立摸牌位、牌谱跳转和结算一致性，以及其他麻将的赤五和叠牌显示。
