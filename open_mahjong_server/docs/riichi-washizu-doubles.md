# 鹫巢麻将（双打）

状态：已实现，2026-10-17 完成服务端、Web、Unity 运行时及 Windows 开发构建验证。规则标识 `riichi/washizu_doubles`，规则版本 `washizu-captain-v1`。

这是开放麻将的线上改编规则。保留现有鹫巢牌池与透明牌机制，以主将成绩决定队伍胜负；不模拟原作现金、血液或后期追加条件。

## 房间与身份

- 四个身份恰各一人：A队主将、A队助手、B队主将、B队助手。玩家面板下拉框直接显示这四项。
- 入座自动分配一个空缺身份。房主选择已占用身份时原子交换两人的身份；普通玩家仅能选择空缺身份，不得替其他玩家换身份。
- 换身份、入座和离座都会增加阵容版本并取消所有准备。旧版本的准备、换身份或开局请求被拒绝。开局后身份锁定，重连恢复原身份。
- 实际行牌顺序固定为 A主将→A助手→B主将→B助手，开局随机整体旋转决定起庄。两位主将对坐，助手坐在所属主将的下家。每局轮庄不改变所属队伍与角色。
- 身份绑定座位中的玩家实例，不以机器人账号 ID 为唯一键；多个同种机器人仍是独立成员。机器人沿用现有合法行动策略，不宣称具备主将制战术。

## 牌局规则

- 默认半庄、每人 25000 点；房间圈数与统一起始点数仍可配置。所有人起始点数相同。
- 136张牌，每种三透一暗；无赤宝牌、无实体牌山、共用随机牌池。每局70次摸牌，包括庄家首摸和杠后补牌，宝牌指示牌另取。
- 头跳、庄家和牌或荒牌流局听牌连庄、不西入；末局庄家连庄继续打，不因主将领先自动结束。保留房间其余合法日麻细则；责任支付关闭。按已有规则处理途中流局，未完成的一局重开。
- 2026-10-18 修正：此前“不连庄”是平台实现限制，不应当作原作要求。授权剧集[第7–8话剧情介绍](https://abema.tv/channels/drama-2/slots/DAUvcLsYRNq31h)明确描述鹫巢战第五回南四局连庄到五本场。该资料证明故事中存在连庄，不作为所有线上改编细则的依据。普通鹫巢、实时手牌和双打均恢复正常庄家连庄；三者的大明杠、加杠按房间翻宝时机向玩家及观战者同步杠宝牌。
- 开启错和时，错和者向其余三人各支付3000点；退还本局已接受的立直供托后检查主将击飞，未击飞则重开本局。
- 队友之间可以吃、碰、杠和合法荣和；点数按通常四人日麻支付。队友自摸照常支付，不免除助手的付款，也不禁止助手和牌。
- 振听、一役起和、食替、立直锁手和吃牌方向等限制继续适用。所有角色立直都需要至少1000点，助手负分后不能借分立直。
- 自己完整手牌可见，其他三家仅透明牌可见；不共享队友暗牌，不新增队内通信渠道。

## 胜负与供托

- 每局结算后，仅检查主将是否低于0点。助手负分不终止对局。恰好0点不算击飞。
- 一位主将击飞时其队负；双方主将同局击飞时，以击飞判定时主将点数较高的一队胜，相同则和局。终场退还供托不撤销已经判定的击飞。
- 未发生击飞时，预定局数完成后比较两位主将最终点数；高者胜，同分和局。助手成绩不参与队伍胜负。
- 单局和牌正常领取供托。终场仍未领取的立直棒按各次出资记录退回本人，不发给个人第一名。已领取的供托不得再次退还。
- 不使用个人顺位点和头名奖励。四人实际点数保留，队伍结果另列；两名队员共享队伍胜负，和局双方各0.5比赛分。
- 牌谱保存规则版本、初始身份与座次、逐局队伍摘要、供托返还明细及最终队伍结果。普通鹫巢与其他立直规则的历史牌谱保持原解释。
- 使用独立子规则统计，不进入普通立直匹配段位；队伍胜负不得由个人点数排序推导。

## 客户端和协议

创建房间时选择「立直麻将 → 鹫巢麻将（双打）」。入房后，每张玩家卡片直接使用四项身份下拉框；对局 HUD、重连快照、牌谱及结算页均保留身份。Unity 对局和牌谱中的身份放在显示报听的共通玩家布局组，独立显示 A队主将、A队助手、B队主将、B队助手；称号栏继续显示玩家称号。结算页按队伍排列，主将在前，同时展示个人点数、所属队伍主将点数与比赛分。

| 数据 | 约定 |
|---|---|
| `team_role_by_seat` | 房间座位顺序；0=A主将、1=A助手、2=B主将、3=B助手，空座为-1 |
| `team_by_seat` | 由身份派生，0=A队、1=B队，空座为-1 |
| `room/set_team` | 提交 `room_id`、`roster_revision`、`seat_index`、`role_id`；服务端校验并广播新阵容 |
| `PlayerInfo.team_id/team_role` | 对局玩家实例的队伍及 `captain` / `assistant` |
| `GameInfo.washizu_doubles` | 按当局座次排列的身份数组与主将点数；允许观战者读取，不含暗牌 |
| 牌谱标题的身份数组 | 按 `original_player_index` 排列；回放通过每局座次映射恢复 |
| `doubles_result` / `team_result` | 主将最终点数、获胜队、判定原因、比赛分、击飞时点数和供托返还明细 |

固定选项在 Unity、Web、Node 和 Python 边界统一执行。普通详细规则的 `end_deposits=discard` 仅用于兼容配置格式；本模式实际结算由 `washizu_doubles_profile.end_deposits=refund_contributors` 接管。队伍结果不采用普通个人顺位结算。

机器人可以占任意身份，但仍使用当前普通行牌策略；专门的主将保护与喂牌策略不属于此版本。
