# Local hint regression fixtures

These golden cases were generated from the Python settlement/shape calculators
on 2026-10-16, using deterministic generated hands and existing rule test hands.
They include legal and rejected shapes, exposed melds, special hands, wildcard
counts, rule switches, ordinary discard wins and self draws. Expected scores do
not assume a future kong, last tile or other incidental event.

`LocalHintValidation.Run()` evaluates all cases in the Unity client. The Web
client's `tests/localHintParity.test.mjs` reads the same fixtures for every rule
with a Web hint calculator. Hong Kong's six scoring profiles currently have a
Unity hint consumer only.

`hongque-parity.json` covers the current win preview, including discard wins,
self draws, heavenly/last-tile conditions and adding a drawn tile to a meld.
Its `local_win_context` packet contains conditions only; the client reuses its
existing cached Hongque scorer. The server no longer calculates this preview.

`snapshot-parity.json` additionally covers each legal discard and all resulting
waits, including locked discards, passed-win restrictions and physical/logical
wildcard mappings. Use `LocalHintValidation.Snapshots(path)` to run this fixture.

Expected values are an independent oracle, not generated by either client.
When changing rule semantics, update the Python regression tests first and
regenerate/review affected expected values before changing these files.

After changing the shared Web calculators, run `npm run build:unity-hints` in
`open_mahjong_web/client`. This packages the same calculators in the Unity WebGL
plugin, without a network dependency. `localHintWebGL.test.mjs` checks the package
matches the source. Desktop/Android use a bounded C# worker; WebGL uses a browser
worker, with Hong Kong quotes computed cooperatively between frames.

Live regional packets now contain `local_request`: a copied own-hand/meld input
and the rule state needed to compute previews. Guobiao wildcard/sixteen clients
already have those inputs and no longer request scoring over HTTP. Deploy the
updated clients with the server: older regional clients cannot calculate from
`local_request`. Existing replay files with precomputed rows remain readable.
Actual win actions, settlement and bot decisions remain server-authoritative.
