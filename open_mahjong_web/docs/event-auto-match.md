# 赛事与基地自动匹配、对局设置预设

## 使用方式

在账户面板的赛事或基地管理中打开「准备组桌」。

- 顶部单独展示「默认配置」。「修改对局设置」展开内嵌编辑面板，在同一个地方维护默认配置和多个具名预设。
- 手动组桌时先勾选 4 名玩家，再打开确认窗口，选择默认配置或某个预设，核对玩家和对局参数后确认。该选择只用于本桌，不会改变默认配置。
- 「自动匹配」位于准备名单下方，选择上方维护的默认配置或预设。这里不再另外编辑一套参数。
- 开启后，游戏服务按准备时间顺序，从在线且当前可以入桌的玩家中每次取 4 人，自动入房并开局；不足 4 人继续等待。管理页面关闭后仍运行。
- 自动匹配启用期间，管理页暂停人工勾选组桌。关闭自动匹配或关闭赛事后停止创建新桌，已经开始的对局继续进行。
- 保存默认配置或预设后，正在使用它的自动匹配会从后续新桌起采用新参数，已经开始的对局不受影响。删除自动匹配当前选择的预设前，需要先切换到其他配置。

国标使用现有完整对局设置表单；其他规则沿用现有赛事建房能力和默认参数。一个赛事或基地最多保存 50 个预设，名称为 1–40 字，同名不可重复。

普通账户、办赛申请等固定宽度面板仍以 1100px 为上限，宽屏下左侧分配三分之一的剩余空间，使面板略向左。赛事和基地管理继续使用全部可用宽度。设置弹窗最大 720px，窄屏保留两侧 12px 空间。

## 保存与接口

使用独立的 `events.room_settings JSONB NOT NULL DEFAULT '{}'::jsonb`，避免公开的 `entry_config` 编辑覆盖私有设置。Node 和 Python 的启动建表逻辑均包含幂等补列。

文档包含 `version`、`revision`、`manual`、`auto_match`、`presets`，当前版本为 2。为兼容现有字段名，`manual` 保存唯一的默认配置，且其 `preset_id` 固定为 `null`。自动匹配的 `preset_id` 为 `null` 时使用默认配置，否则引用具名预设；`room_rule`、`room_config` 是同一事务中从所选配置派生的快照，供现有 Python 匹配服务读取。

版本 1 的独立自动匹配参数会被保留：与默认配置或现有预设相同时直接引用；否则转换成名为「原自动匹配设置」的预设。读取时完成确定性的兼容转换，首次成功写入时持久化，避免改变旧比赛所用的规则。

以下接口均位于 `/api/event-admin/events/:eventId`，需要本赛事的 owner/admin 权限：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/room-settings` | 获取整份设置与预设 |
| PUT | `/room-settings` | 保存默认配置 |
| PUT | `/auto-match` | 保存所选预设与自动匹配开关 |
| POST | `/room-presets` | 新建预设 |
| PUT | `/room-presets/:presetId` | 修改预设 |
| DELETE | `/room-presets/:presetId` | 删除预设 |
| GET | `/auto-match` | 查询游戏服务运行状态 |
| POST | `/seat` | 按确认选择的配置安排本桌 |

设置写入携带当前 `revision`。同一 SQL 事务中锁定当前赛事行、复查管理权限、修改文档并写审计记录。版本冲突返回 409 和最新文档，界面保留尚未保存的设置草稿，提示核对后重试。

自动匹配保存请求只提交 `{ revision, enabled, preset_id }`，服务端解析默认或具名预设，不能夹带另一套自定义参数。手动确认请求为 `{ user_ids, revision, preset_id }`，服务端核对 4 个不重复的有效玩家 ID、权限和设置版本，解析本桌参数后调用 Python；此操作不修改默认配置或设置版本，也不持有数据库行锁等待 Python 开桌。

游戏服务内部接口为 `GET /admin/event/auto-match?event_id=…` 和 `POST /admin/event/auto-match/refresh`。运行状态包括后台任务、有效等待人数、服务本次运行中的匹配桌数、最近匹配时间及错误。Web 服务无法连接游戏服务时，状态查询返回 503；如果设置已经成功入库，保存仍返回成功并说明稍后生效。

## 匹配与失败恢复

后台任务每 2 秒检查开启中的赛事，也会在玩家准备或管理员保存设置后被唤醒。人工和自动组桌共用锁并预留玩家，认领 4 条准备记录的数据库事务必须全部成功，防止同时操作重复拉人。

入桌前检查在线连接、当前房间、进行中对局、排位队列、报名与准入条件，并退出原有延时、实时观战及待响应观战申请，防止旧局继续推送。观战进入与组桌互斥，异步退出后重新核对玩家状态。自动开局前再次检查连接、赛事状态和匹配参数。通知、入桌或开局失败时清理新房间并恢复仍有效玩家原本的准备时间；已主动离开或断线的玩家不会被重新入队。已有游戏状态按现有服务的生命周期管理。
