# 牌底接触阴影

主工程的 `New Universal Render Pipeline Asset_Renderer` 中使用 **Tile Contact Shadows**。普通牌统一采用“卡通受光 + 牌底软影”：牌体保留方向光控制的亮暗分区与几何描边，桌面阴影完全由独立软影生成。普通牌不再投射或接收实时阴影；场景光源与其他物件的阴影设置仍可独立控制。实现使用本项目自己的网格和程序渐变。

在 Unity Project 中选中 `Assets/URP/New Universal Render Pipeline Asset_Renderer.asset`，展开 **Tile Contact Shadows → Settings** 即可调整。运行时所有已取出的池对象都会在下一次渲染使用新值，不需要重新放牌。

| 参数 | 初始值 | 作用 |
| --- | --- | --- |
| Enabled | 开启 | 开关牌底软影；关闭后普通牌没有桌面投影 |
| Opacity | 0.90 | 立牌贴桌时的基础浓度；建议在 0.85–0.95 间微调 |
| Flat Opacity Ratio | 0.60 | 平躺浓度相对基础浓度的比例；默认实际浓度为 0.90 × 0.60 = 0.54，设为 1 恢复横竖同浓度 |
| Feather Ratio | 0.26 | 从牌底轮廓向外渐淡的距离相对牌宽；越大扩散越宽，不改变牌体 |
| Fade Height Ratio | 0.65 | 离桌达到这个牌宽倍数时完全消失 |
| Lift Spread Ratio | 0.08 | 抬牌时增加的最大扩散半径相对牌宽 |

牌宽为 12 世界单位时，默认向外扩散距离为 3.12，离桌 7.8 后完全消失。高度以现有贴桌留空量为零点，默认留空量仍是 0.02。低处浓、外侧淡；抬起时变宽并淡出。上层叠牌不会在桌布重复画一块浓影。

外缘令 `t = saturate(1 - distance / feather)`，使用 `t² × (3 - 2t)` 平滑衰减，Opacity 默认为 0.90。2026-09-24 调整：原来的 0.72 浓度 / 0.48 扩散在浅色纹理桌布上形成宽灰晕，因此收窄为 0.26，并把贴地浓度提高到 0.90。保留连续软边，让暗部集中在牌底。不同桌布、相机和模型投影会影响最终像素颜色与形状，这组值是主项目原相机下的视觉匹配参数。需要收窄时优先调整 Feather Ratio；需要整体变淡时调整 Opacity。

软边从牌底轮廓向外衰减，避免把一半渐变藏在不透明牌体下面。立牌、倒牌、横向副露、暗杠和牌谱展开手牌都使用实际牌体范围与同一桌面平面，不按玩家方位或玩法设置额外偏移。

平躺牌使用较浅的接触阴影。投影时用实际牌面（模型 XY 平面）的法线与桌面法线的绝对点积，连续插值到 Flat Opacity Ratio；正面朝上、背面朝上、四家朝向和横放共用这一规则。立牌保留 0.90，完全平躺使用 0.54，池对象不需要重新生成。这些参数用于本项目的牌体、桌布和相机。

翻牌中段只有边角贴桌，完整包围盒投影会露出过大的深色矩形，因此按包围盒面与桌面的贴合程度平滑淡化。接近完全立起或放平时恢复正常浓度。计算使用完整变换矩阵和变换后轴的叉积，兼容父级非均匀缩放；没有 Animator 状态名、座位或模式分支。

`TileContactShadow` 挂在现用牌预制体的牌体根节点上。预制体的 Cast Shadows / Receive Shadows 均关闭，组件每次启用时再次统一这些状态并注册；回池、禁用或销毁时移除。`Game3DManager.ContactShadows` 注册现有桌布接触面的动态查询，复用自动贴桌系统的桌布子网格/显式平面。渲染阶段读取最终变换，所以兼容对象池复用、四家朝向、翻牌与父级缩放。独立牌面预览没有桌布注册时不画阴影。

`ThreeDTiles` 已移除 ShadowCaster Pass、实时阴影采样和对应变体，旧 `_TileShadowStrength` 参数及其编辑器同步入口已删除。牌体暗面颜色仍在共享 `3DTile.mat` 的 **Tile Shadow Tone** 调整；底部软影浓度在 Renderer 的 **Opacity** 调整，两者互不混用。

维护预制体时必须保留根 GameObject 的 local fileID `7964087330845181315`，以及原预制体 GUID `b6b976a95574b80408d5b773b7834bb2`。新增组件引用根对象时也使用这个 ID；为导入模型的根对象添加 `stripped` 序列化记录不能另造 ID，否则既有场景中的对象池、牌桌和预览引用都会失效。检查时除按路径加载预制体，还要验证真实场景的反序列化引用。

实现共用一张四顶点、两三角形的程序矩形网格和一个材质，每批最多 128 张牌。片元程序计算圆角矩形的柔和边缘，不采样贴图；仅在牌底附近混合颜色，使用现有场景深度遮住牌体。没有新增全屏 RenderTexture、深度复制、模糊或每牌 Update。成本包括 CPU 投影计算、每牌两个三角形和局部透明混合；同时省去牌体的实时阴影图绘制和阴影采样。支持实例化的平台每 128 张以内通常提交一批，不支持时逐牌提交。实际 Web 帧时仍取决于设备，应在目标浏览器上测量。

接触阴影 Shader 保留在 Graphics 的 Always Included 中，同时提供 `Assets/Resources/Materials/Tiles/TileContactShadow.mat`，其 GPU Instancing 必须开启。Renderer 在初始化时复制这个共享模板；运行时只更新批次属性。本次独立 Win64 构建验证发现，仅依赖运行时创建材质会丢失实例化变体，出现“提交了绘制但没有软影”的情况。模板既是实际材质来源，也让构建器识别实例化用途；不要删除它或关闭其 GPU Instancing。

**打包必须保留实例化变体：** `Project Settings → Graphics → Shader Stripping → Instancing Variants` 使用 **Strip Unused**，不能使用 **Strip All**。主项目此前仍设为 Strip All，会在构建时剔除阴影需要的实例化变体；Editor 预览正常不能证明桌面客户端正常。已将主项目改为 Strip Unused，由上述实际材质保留所需变体。修改后必须重新构建客户端，现有 EXE / Data 文件夹不会随 Editor 设置更新；发给其他使用者时需更新完整构建目录。

两个以 Scene 为键的桌面缓存共用无装箱比较器，以避免默认 Dictionary 比较带来的临时分配。扩大软影会增加局部片元覆盖和混合量，绘制批数与顶点数不变；性能应按当前参数在目标设备上测量。
