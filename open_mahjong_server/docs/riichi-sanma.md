# 三人立直麻将

三麻作为日麻族的子规则 `riichi/sanma` 接入，复用既有计番、立直、振听、抢杠、多响、包牌和终局流程。房间的 `room_rule` 仍为 `riichi`，普通建房和场馆组桌均按三席处理；四人标准日麻与浪涌仍按四席处理。

## 规则与预设

| 项目 | 三麻设计 |
| --- | --- |
| 玩家与场次 | 东、南、西三家；每圈三局，东风三局、半庄六局，连庄另计 |
| 牌种 | 移除二至八万及赤五万，保留一万、九万、筒、索和七种字牌，共 108 张 |
| 赤牌 | 开启时各一张赤五筒、赤五索 |
| 鸣牌 | 禁止吃，允许碰、明杠、暗杠和加杠 |
| 万子宝牌 | 一万指示九万，九万指示一万 |
| 北 | 可作为手牌使用，也可在自己的摸牌操作中拔出；拔北不破坏门前清 |
| 起始与目标点 | 默认每家 35000 点，目标 40000 点 |
| 本场 | 自摸每名实际付款者支付 100，荣和放铳者支付 300 |
| 荒牌罚符 | 总额 3000，按实际听牌与未听牌人数分配；全听、全不听不支付 |

| 预设 ID | 界面名称 | 起始／返还点 | 顺位点 | 自摸 |
| --- | --- | --- | --- | --- |
| `sanma_majsoul` | 雀魂三麻 | 35000／35000 | +15 / 0 / -15 | 自摸损 |
| `sanma_tenhou` | 天凤三麻 | 35000／40000 | +20 / 0 / -20 | 自摸损 |

默认选雀魂三麻；选择三麻预设同时切换子规则和基础设置。选择四人预设会切回四人标准日麻，避免把三人顺位点用于四人房间。天凤预设的起始与返还点差额按三名玩家计算头名奖励。

两套三麻预设均关闭四风连打、四家立直，采用多家荣和，默认允许普通合法和牌抢拔北、拔北补牌成立岭上开花。保留已有日麻详细设置，允许房主改为头跳、国士限定抢北等变体。预设按本项目可表达的规则范围实现，规则目录是实际执行配置的依据。

## 拔北操作与计分

拔北动作是 `nuki`，客户端显示“拔北”。玩家可选择拔手中的北或刚摸到的北；已经立直时只允许拔刚摸到的北。碰后尚未摸牌、无北、剩余活牌为零或补牌次数已达上限时不能拔北。

流程为声明、检查抢北、确认移除北、补牌。抢北成功时只移除被抢的一张北，不记拔北宝牌、不补牌，也不翻杠宝牌；其他玩家过和或超时采用既有振听规则。拔北会中断一发及首次行动相关的双立直、地和、九种九牌条件。

每张已拔北计一番宝牌，并按宝牌／里宝指示牌继续叠加；开启里宝且玩家已立直时才计里宝。留在手中的北按正常字牌计分，在三人席位中是客风。拔北宝牌不能单独构成役，也不叠加到真正役满上。

新增三项详细配置，与原有选项合计 40 项：

| 键 | 值 | 含义 |
| --- | --- | --- |
| `sanma_tsumo` | `loss` / `split` | 两名实际玩家按原本各自付款，或把缺席第四家的份额均分给二人，各份向上取整到 100 点 |
| `nuki_ron` | `all` / `kokushi` / `none` | 所有有役合法和牌可抢北、仅国士无双可抢北、禁止抢北 |
| `nuki_rinshan` | `true` / `false` | 拔北补牌是否赋予岭上开花；关闭时补牌也不赋予海底摸月 |

例如非庄满贯自摸，自摸损时收 4000 + 2000 = 6000；分摊模式收 5000 + 3000 = 8000。庄家满贯自摸分别收 8000 或 12000。本场、供托、责任支付在基本点数之后处理，真实和牌分变始终由服务端下发。

## 牌山、补牌与宝牌

配牌每人 13 张，剩余 69 张中活牌数为 55，流局时保留 14 张。杠与拔北共用最多八次补牌，杠本身最多四次。拔北不增加杠次数，不翻杠宝牌。

宝牌和里宝各五个位置在开局保存。前四次补牌从尾部取；后四次跳过十张指示牌，从它们前方取牌。普通摸牌仍从头部取。这样即使末巡连续拔北和开杠，未翻开的杠宝牌、杠里宝牌也不会被摸走。记录与 Unity 回放使用相同顺序，不以牌面相等判断物理牌身份。

## 服务端、客户端与记录

- `sanma.py` 集中人数、起始点、万子指示牌循环、补牌位置和自摸付款政策；`nuki_actions.py` 负责拔北声明与提交。
- 所有行动、换庄、场风、罚符、多响、包牌、错和、顺位点和供托使用实际人数。机器人支持拔北。
- 房间容量、准备、座位移动、场馆手动／自动组桌和数据库准备池事务均按三席执行。
- 实时广播沿用日麻消息族；拔北为 `nuki`，补牌为 `deal_nuki_tile`。重连保留三人配置、手牌摸牌槽、已拔北和待抢北状态。
- 录像标题标记 `sub_rule` 与 `player_count=3`；`seats`、起始点、和牌／流局分变、最终实点和顺位点为三元素数组。`nuki` tick 格式为 `["nuki", seat, 44, "T"或"F"]`，补牌 tick 为 `["nd", tile]`。
- Unity 桌面使用本家、右家、左家，顶席空置；实时与录像均支持拔北展示。录像解析、逐步播放、跳转、换视角、局间累计分和计分板支持三人数组。四人界面使用的内部数组可补零到四位，补位不成为参赛者。
- 统计摘要读取三人座位和分变，拔北不计副露，补牌不轮转行动者，不生成第四名统计。旧累计表的模式保留场次分数（如 `1/4`），三麻加 `_sanma` 标记，有段位模式仍以 `_rank` 结尾。


Unity Editor 与最终 Windows 开发客户端均通过 `RiichiSanmaValidation.Run()` 的 89 项本地计分、协议、座位和计分板校验，以及 `RiichiScoreHistoryValidation.Run()` 的 47 项四人供托回归。三人／四人／三人计分板切换通过 41 项检查，包含姓名、局计、总计、主番列对齐和场风标签；八场牌谱的 24 局、2628 帧通过 67824 项逐动作比对。Windows 客户端构建成功，编译错误为零。

本机三个独立 Unity 客户端已分别完成雀魂三麻与天凤三麻的三局对局，验证真实建房、加入、准备、拔北按钮、重连、终局和云端牌谱取回；第四名玩家加入三席满房会被拒绝。延时观战验证服务器既有的 180 秒等待、初始牌谱、增量更新、终局完整牌谱及 Unity 模式切换。观战终局标题合并正式牌谱结算后的三人／四人最终实点、供托和顺位点，开局缓存不提前暴露终局字段。
