# 平台排位评分

国标使用原有段位 PT；立直使用 M 规比赛分驱动的争一 PT，两者均不计算或展示 Elo。青雀、虹雀、川麻血战和血流换三张使用各自独立的 Elo 池，初始 R 为 1500。自定义房间和赛事不进入这些匹配评分池。猜番对抗使用网页服务的独立算法。

## 立直：M 规争一段位

新建的六个立直匹配队列统一使用 `mleague` 房间预设。比赛分 `M = (终局点数 - 30000) / 1000 + 顺位奖励`，一至四位的奖励为 `+50/+10/-10/-30`，一位的 +50 已包含头名奖，不再重复加算。段位计分为 `PT = q × (k × M - C)`：半庄 q=1，东风 q=0.7；初级、中级、高级 k 分别为 0.3、0.6、1。C 按当前段位和场次配置，对各名次扣相同数值，负数是保护奖励。

七段高级半庄 C=5.25；40000/30000/20000/10000 点对应 M 为 +60/+10/-20/-50，PT 为 +54.75/+4.75/-25.25/-55.25。完整的场次、扣分、升降段表和舍入约定见 [立直段位计分](riichi-rank-progression.md)。

段位名称、升降段门槛、现有 PT、管理员调整和十段永久称号保留。算法版本为 `riichi_mleague_pt_v1`，在创建排位局时固定；切换前已开始的对局沿用 `grade_place_pt_v1`。不重算历史段位。结算缓存先于算法校验读取，重复结算返回原结果；新结算同时保存 M、k、q、C、版本和玩家输入，缺失比赛分时回滚，不能退回按名次计 PT。

## 四人 Elo：2400 分母与低分保护

虹雀半庄（8局）使用 K=16，全庄（16局）使用 K=32，两种局制共用虹雀 Elo 池；其他 Elo 规则保持 K=32。只比较最终名次，不计算点差。对玩家 i 和三个对手 j：

```
Eij = 1 / (1 + 10^((Rj - Ri) / 2400))
T = max(0, 1500 - 四人平均 R)
E保护ij = 1 / (1 + 10^((Rj + T - Ri) / 2400))
Sij = 胜 1、并列 0.5、负 0
普通变化 = (K / 3) × Σ(Sij - Eij)
保护奖励 = (K / 3) × Σ(Eij - E保护ij)
新 R = 原 R + 普通变化 + 保护奖励
```

指数限制在 -16 至 16。普通变化先保留两位小数，末位玩家吸收舍入余差，保证普通部分合计为零；每人的保护奖励另外舍入到两位，再相加。末位指终局结算列表的最后一位，列表按得分降序、原始风位升序排列。

桌均 R 不低于 1500 时没有保护奖励。保护不设个人硬保底，低分桌的总变化可以大于零。K=32、四人均为 1500 时，一至四名分别变化 +16、+5.33、-5.33、-16；四人均为 1000 时分别变化 +19.77、+9.10、-1.56、-12.23。虹雀半庄 K=16 的对应结果为 +8、+2.67、-2.67、-8，以及 +9.88、+4.55、-0.79、-6.12。K 同时作用于普通变化和保护奖励，不能把已经舍入的旧增减直接减半。

虹雀结算算法版本为 `hongque_elo_2400_length_k_v2`；新结算和牌谱评分片段保存 `rating_k`。其他规则保持原算法版本与系数。

### 虹雀局制系数的一次性历史重算

运行 `python scripts/rebuild_hongque_elo.py` 预览，核对后使用 `--apply --report <报告路径>` 执行。脚本使用 `HONGQUE_ELO_DATABASE_URL`，未设置时读取服务器的 `local_config/test_config.Config`；执行前应确认连接的是目标数据库，并让服务器加载新的结算代码。

脚本只重建虹雀匹配历史。半庄、全庄从初始 R=1500 按结束时间混合重放，同一时间按牌谱 ID 排序；旧增减分不用于反推名次。当前 Elo、匹配计数、牌谱评分片段和结算重试缓存在同一事务更新，其他规则及自定义牌谱保持原样。缺少牌谱、局制、有效名次或历史不足时中止并回滚。

重算使用全局评分写锁；修改前的评分、完整牌谱和结算缓存保存在 `hongque_elo_rebuilds.backup`，完成标记与更新一并提交。重复执行会返回已完成结果，不会撤销后续新对局。没有虹雀匹配历史时不写完成标记。正常启动不重放历史、不增加旧格式兼容分支。

## 已完成的历史重算与正常启动

发行版 26 已完成并验证历史重算，一次性重建代码和启动钩子已归档。正常初始化仅保留评分表、约束及默认值，不再在重启时全量重放或重置玩家评分。新数据库从 1500 开始正常结算，不依赖历史迁移表。

旧库保留 `rating_rebuild_migrations` 中的 `elo_2400_table_protection_v1_grade_without_elo` 审计标记和备份。当时的重算从 1500 完整重放青雀和川麻的历史匹配局，按牌谱结束时间排序，同一时间按牌谱 ID 排序。旧的无时区结束时间按北京时间解释。

已完成的重算更新了当前 R、匹配计数、牌谱内评分结果和结算重试缓存；没有历史的 Elo 玩家恢复为 1500/0 场。删除账号仍参与历史预期计算，但未重建账号。国标、立直的 Elo 字段已置空，历史结果中的 Elo 信息已删除，原有段位、PT、管理员调整及段位匹配计数保留。

重算时使用全局评分锁防止与新结算交错。旧评分、缓存和改动前的牌谱评分片段保存在迁移记录的 `backup` 字段；所有修改和完成标记在同一事务提交。保留这些审计数据便于追溯及回退，但正常启动不会再读取标记来触发重算。

新结算保存玩家/名次输入和结束时间，牌谱通过 `rating_game_id` 关联运行时结算 ID。历史验收将旧牌谱与原评分结果精确关联；缺失牌谱、输入或有效历史名次/结束时间时不能从旧增减分猜测名次，也不能静默丢弃对局。本次验收覆盖的 Elo 历史已全部对齐。
