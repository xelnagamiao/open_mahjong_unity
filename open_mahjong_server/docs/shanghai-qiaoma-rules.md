# 上海敲麻

规则标识为 `room_rule=shanghai`、`sub_rule=shanghai/qiaoma`。建房面板的上海麻将版块依次展示上海敲麻、清混碰，本文说明敲麻规则。

## 依据与房间约定

依据用户提供的《上海麻将（推广）竞赛规则（试行2024版）》，行牌、报听、和牌和计分主要见第 6—10 页。原 PDF 收录在 Web 项目的 `client/public/rulebooks/shanghai-qiaoma-2024.pdf`，网站规则书页可阅读。

- 144 张牌。中、发、白及八张花牌必须补花，不参与面子与将牌。补牌从牌墙末端取，无保留尾墩。
- 四面子一将，不承认七对等特殊牌型。先敲牌再打出声明牌；敲牌后锁手、不能吃碰，合法和牌强制执行。合法杠须保留听牌结构；有花时，摸到已碰牌的第四张强制加杠。
- 支持食替限制、过碰限制、抢加杠、一炮多响、首次补花顺序及花牌连续补牌。线上所有实际操作询问统一使用房间配置：默认每步 5 秒、每位玩家每局额外思考时间 20 秒，先耗步时，再消耗本局剩余局时。吃碰杠和、抢杠、报敲选牌与补花均无独立 3 秒上限；首次补花后的报牌也使用同一合同。
- 房间局数为 4、8、12、16 副实际牌局。服务端沿用公共 `game_round=1..4` 字段，每档对应 4 副；连庄也消耗一副。第一副东家坐庄，单人和牌由和牌者坐庄，荒庄连庄，一炮多响由点炮者坐庄。
- 使用项目既有的局时、步时和准备机制。线下裁判判罚、赛事检录、盘间时间及赛事名次分不由私人房间自动执行；非法牌操作由服务端拒绝。

## 线上计时补则

房间自定义步时与局时原样生效；局时 0 表示没有额外思考储备，仍享有房间步时。步时内完成操作不扣局时，超出步时的实际秒数扣除储备，内部保留不足一秒的余额，协议及倒计时向上取整显示。吃碰成立后的出牌、每次实际补花询问都开启新的步时，沿用同一玩家本局尚未用完的局时；下一局将储备恢复为房间局时。

询问按首次实际发送到该座位的时刻起算，按服务端接收有效操作的时刻结账；广播其他座位、观战发送和后续处理的等待不重复计费。重连和重复补发投影原窗口，不重新给步时、不改变截止点、不扣第二次局时；已回应者不会再次收到旧询问。预算耗尽后鸣牌默认过牌，手牌默认合法出牌，有花仍执行必须补花，敲后强制和牌及强制加杠沿用原有语义。报敲选牌及取消都留在同一个出牌窗口。

`remaining_time`、`step_remaining` 保留向上取整的整数秒兼容字段；敲麻另发 `remaining_time_ms`、`step_remaining_ms`，供当前客户端按毫秒预算确定截止点，避免把两个取整字段相加后获得额外时间。服务端时钟使用单调时间；Unity 扣除本机收件到呈现之间的排队时间，并使用真实时间截止点，暂停和长帧不会延长倒计时。Web 目前只开放国标实时牌桌，敲麻仍通过 Unity 对局；共用 Web 适配器已兼容上述可选字段。

上述线上约定优先于原 PDF 的线下报牌时限；原始规则书保持原文存档。

## 计分

基本分为 `(1 + 非底花数) × 2^min(番数, 3)`。

补花每张 1 花；序数明杠 1 花、暗杠 2 花；风刻 1 花、风明杠 2 花、风暗杠 3 花。花数为零时按无花 10 花计，与实体花数不叠加。

门清、大吊车、杠开、抢杠、混一色、碰碰和各 1 番，清一色 2 番。无常规番种时，2 花起自摸、3 花起点和；杠开和抢杠不取消此门槛。

建房可开启“一番和”，默认关闭。开启后要求总番数至少 1 番（包含杠开、抢杠），0 番垃圾和不可和；花数、无花奖励不算番，原有花数门槛仍生效。此选项仅用于敲麻，以 `hepai_limit=0/1` 传递，写入房间、重连/观战信息及牌谱；缺省按关闭处理。听牌和敲牌仍按牌型结构判断，和牌资格由服务端最终审核。

普通点和由点炮者支付一份基本分，自摸由其余三家各付一份。有承包时，自摸由每个承包人支付五份，其他人不支付；点和向点炮者及每个承包人各收一份，点炮者未敲牌则代付全部。

**重合身份约定：**规则书第 9 页未单独示例点炮者同时为承包人的情况。本实现暂按点炮身份和承包身份分别计算，即该人支付两份基本分；待规则解释确认后可在独立结算函数 `payments()` 中调整。其他支付关系保持零和。

承包关系为双向，可同时存在多组。只累计供牌人在敲牌之前打出的牌；其声明牌也不计入。三副同源且公开面子符合碰碰和、混一色或清一色条件即成立；第四副破坏全部条件则解除，四副同源无条件成立。

## 接入

- `server/game_calculation/shanghai/qiaoma.py`：标准手牌拆解、听牌、花数、番种、支付计算。
- `server/gamestate/game_shanghai/ShanghaiGameState.py`：回合规则、敲牌、承包、强制操作、结算及庄家衔接；复用台湾状态机已有的并发响应、重连和观战基础设施，通过规则钩子隔离差异。
- `server/gamestate/game_shanghai/bot.py`：在合法敲牌与食替约束下使用公共牌效机器人。
- `server/room/room_router.py`：`room/create_Shanghai_room` 路由；房间校验器检查子规则及一番和选项。
- Unity `Assets/Scripts/GameScene/Rules/Shanghai/`：规则注册、锁手表现、听牌和基本分提示。客户端提示是普通和牌的基本分，偶然番与承包支付以服务端结算为准。
- 敲牌和承包标签写入牌谱；回放复用公开报听状态与尾部补牌处理。数据库沿用通用牌谱及玩家记录表，保存 `shanghai/qiaoma` 标识。

## 回归测试

在服务端目录执行：

```powershell
.venv/Scripts/python.exe -m pytest server/game_calculation/shanghai server/gamestate/game_shanghai server/gamestate/game_taiwan/test_taiwan_rules.py server/room/test_pointer_tips.py -q
```

独立牌例覆盖最低花数、偶然番限制、无花、封顶及承包支付。状态机测试覆盖声明锁手、连续补花、合法杠、抢杠恢复、一炮多响、承包建立与解除、超时及重连。整场测试由四个协议客户端驱动真实操作队列，使用三个固定随机种子各打完四副，检查结算零和、牌谱、庄家衔接及房间清理。
