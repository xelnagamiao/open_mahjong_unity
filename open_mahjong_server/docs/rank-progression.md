# 国标段位升降规则

排位结算使用 `server/match/rank_calculator.py` 中的配置。Excel 配表不会在运行时自动加载。

| 段位 | 升入时 PT | 升段门槛 | 掉段条件 | 结算规则 |
| --- | --- | --- | --- | --- |
| 九段 | 3200 | 7000 | PT 小于 0 | 正常加扣 PT，达到门槛升十段 |
| 十段 | 100 | 无后续段位 | 不掉段 | 固定 100/100，后续对局 PT 变化为 0 |

九段的 3200 是升入时的起始分，不是保底分。九段结算后的有效 PT 为 0～6999.99；低于 0 时降到八段起始分 1600。

升入十段时丢弃溢出 PT。例如九段 6999 PT 获得 84 PT 后，结果为十段 100 PT。晋升当局仍显示所获的 84 PT，此后的十段对局均显示 0 PT 变化。

其他段位沿用原有规则：达到门槛可连续升段，溢出 PT 带到下一段起始分；降段单次最多一段。

## 配表版本

- `other/RankTable.xlsx` 的 `Sheet1!B26:G27`：九段为 3200/7000，十段仅写“保留称号”。当前代码沿用这份表的九段门槛。
- `other/RankTable_updated.xlsx` 的相同区域：九段起始分为升段分的一半，即 4000/8000，十段同样仅写“保留称号”。这份表的九段数值未应用到当前代码。
- 两份表第 30 行以下是“天凤数据参考”，不作为平台配置。本次未修改两份 Excel。

Python、Web 服务端、Web 前端和 Unity 的段位表需同步更新。十段对应索引 19，以确保场次资格、排行榜和升段动画正确识别。

## 生效范围

修改代码后需要更新并重启 Python 服务和 Web 服务，同时发布新的 Web 前端及 Unity 客户端。代码修改不会直接更改已存在的数据库记录。

历史上已超过门槛但停留九段的记录，可在管理后台核对后设置为十段 100 PT；如果等待下一次排位结算，则按该次结算后的总 PT 判断是否达到 7000。已有十段记录在下一次排位结算时会统一为 100 PT。
