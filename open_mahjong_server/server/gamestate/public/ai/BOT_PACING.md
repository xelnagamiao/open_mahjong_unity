# 房间机器人节奏

房间 `bot_speed` 统一使用 `instant`（极快，0 秒）、`fast`（快速，默认，0.5 秒）、
`medium`（中等，1 秒）、`slow`（慢速，1.5 秒）。旧 `standard` 值兼容为 `fast`。
Unity 和 Web 在空玩家位置显示机器人添加按钮；有机器人时，在开始按钮左侧显示速度下拉。
房间面板在开局前调用 `room/set_bot_speed`；
服务端校验房主、房间归属及开局状态，然后通过 `room/refresh_room_info` 同步。
改速度保留准备状态；加入的新机器人也使用该设置。开局时复制到独立对局快照。

## 所有规则共用的基础计时

基础速度不依赖鸣牌保护开关，覆盖所有允许机器人的规则：国标、青雀、长沙、四川
（含血流两种玩法）、立直（含浪涌）、古典、台湾、上海（敲麻／清混碰）、中庸／南雀、
虹雀、香港（清章／新章十三张／新章十六张），并兼容南雀的旧 Jiandan 协议入口。
自由模式本身不支持添加机器人，界面不显示机器人速度入口。

`pacing.py` 管理人工等待，AI 计算耗时计入目标间隔，不再先等再计算。
公共动作协议在提交前复核行动帧、等待席位和对局生命周期；无需动作的 pass 不额外等待。
极快不添加机器人思考等待；网络与合法行动时机仍正常处理。
虹雀使用同一速度表和等待函数，保留其独立动作协议和亮牌响应策略。掉线真人继续使用托管策略。

## 机器人房与鸣牌保护

只要房间有机器人，鸣牌保护就不生效。房间面板、开局与重连数据均显示实际关闭状态。
创建房间时选择的开关保存在房间内；移除最后一个机器人后恢复该选择。
所有机器人类型和支持保护的规则使用同一判断，空座位与掉线真人不算机器人。

机器人按所选速度计算、等待并通过原状态机提交动作，各玩家正常收到广播。
不再提前提交弃牌，不再保存机器人展示时钟、上一张弃牌锚点或分视角补时。
吃碰后的出牌也只走统一机器人计时，不叠加鸣牌保护等待。

纯真人房仍可使用鸣牌保护，支持国标、青雀、长沙、四川、中庸／南雀、旧简单入口及立直。
隐藏弃牌、保护超时、实际送达后的鸣牌间隔、操作计时及重连 FIFO 保持。
战术鸣牌是独立规则，不因添加机器人而自动关闭。机器人房不承诺隐藏响应等待信息。

回归测试：`public/ai/test_pacing_all_rules.py` 验证各真实状态类的房间速度配置，以及
各机器人入口的四档速度、计算耗时计入间隔、吃碰后出牌和保护开关兼容性。
保护展示层由 `public/test_claim_protection_pacing.py`、各规则的 `test_claim_protection.py` 覆盖。
两真人两机器人及所有座位组合由 `public/test_bot_room_claim_protection.py` 覆盖；
房间加减机器人、恢复保护开关和速度权限由 `room/test_claim_protection.py`、`room/test_bot_speed.py` 覆盖。
