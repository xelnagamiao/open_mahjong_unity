# 贵州 MIL 2023 的听牌提示

对局稳定听牌、切牌预览、牌谱及延时观战保留物理可和的四面子一对 / 七对待牌。基本牌形成立就展示，不按点和资格删去待牌；自己手牌和副露已经占满四张的牌不会再显示为可和的第五张。流局查叫的理论听牌仍由服务端独立计算。

提示显示贵州基本分，39 分封顶。普通平和 3 分；大对子 8 分；清一色、七对、四副露单吊各 13 分；龙七对 26 分；软报加 13 分，原报加 26 分。无其他番时才使用平和 3 分；四副露单吊不再叠加大对子 8 分；多个牌型按服务端最高基本分取值。

可普通点和显示绿色“X分”。只有普通平和且没有明杠或暗杠通行证时显示橙色“仅自摸 3分”，碰牌不算通行证。贵州没有起和分门槛，合法物理待牌均可自摸，显示分值或“仅自摸”，不会因分低显示“未起和”或“未满足”。“未满足”只用于牌形、数量或实体张数等硬约束不成立的防御性回退；这些输入会被物理待牌筛选排除，不代表起和分不足。其他规则分数不足的共用“未起和”文案保持原意。余张为零沿用现有灰色显示。牌谱头像紧凑听牌条只显示牌张及余张，用同样颜色；展开提示显示基本分。Web 牌谱沿用“仅自摸”的简短标签，内部自摸分和单位仍为贵州基本分及“分”。

原报、软报从当前服务端本家快照读取；等待选牌确认的软报切牌预览按软报计算。玩家和观战恢复时，在载入报听状态后立即重建听牌入口，不依赖下一条询问或既有缓存；真实摸入张只从提示查询副本去除，手牌副露与原实体牌不改。关闭提示及终局阶段隐藏入口。新局与退出房间清空本家缓存。旧服务端包仍可从手牌询问和报听动作读取已存在的 `ready_qualification`。牌谱按当前节点读取本座位报听事件，前后跳转不能带入未来报听；牌谱提示不读取实时对局缓存。

按用户明确要求，提示不适配过水、永久禁点和和天和 / 杠开 / 热炮 / 抢杠等临时条件；实际操作合法性及最终分值由服务端判断。鸡与杠账本另计，不把未来账本收支当成提示基本分。牌谱铳牌危险标记只使用这些普通提示中可点和的牌，不标记仅自摸；同样不额外预测过水或偶然役。

Unity 接入点：`GuizhouShape.Waiting`、`GuizhouTips.Describe`、`GuizhouRuleBootstrap.RecordDangerUsesWaitHint`。Web 接入点：`calc/guizhou/waitTips.ts`、`guizhouReadyAt`、`Replay.vue` 的贵州分支。Web 2D 实时对局仍只接入国标，这次变更只覆盖已接入的贵州牌谱。

回归入口：服务端 `test_hint_context.py` 与 `game_calculation/guizhou/test_rules.py`；Web `guizhouWaitTips.test.mjs` 与 `guizhouReplay.test.mjs`。普通时钟与战鸣独立再询问合同见 `TIMING.md`，提示改动不改变这些计时路径。
