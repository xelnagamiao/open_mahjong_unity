# 复式牌墙与密钥权限

新的“复式”仅用于国标麻将，一把密钥保存 1、4、8、12 或 16 局牌山，供多桌按相同局序比赛。旧版各规则按随机种子重放整场的功能仍称“场景复现”，与此数据模型分开并保留。

## 数据表

Web 的 `open_mahjong_web/server/utils/duplicateTables.js` 与游戏服务的 `duplicate_walls.py` 在启动时创建相同表；不改写既有牌谱 JSONB 表。

`duplicate_walls` 保存 `id`、随机唯一 `key`、`owner_user_id`、`event_id`、`scope`、`wall_type`、`rule`、`use_flowers`、名称、首局 `tiles` JSONB、`round_count`、逐局 `round_tiles` JSONB、整场 `seed`、`is_unlocked`，以及创建、首次解除锁定、结束、软删除时间。升级时先增加可空的 `use_flowers`，按旧墙实际是否含 51–58 花牌回填，再设非空及默认值；不改写旧牌序、种子、锁定状态或时间。

- `scope = personal`：个人账户每天创建 5 把密钥，同时保存 25 把。局数不改变额度计数。
- `scope = event`：同一比赛的所有管理员共用每天 20 把密钥、同时 100 把。每次管理重新校验 `event_admins` 成员身份；仅 `kind = event` 且状态为 `registered` 或 `active` 可新建，基地及关闭的比赛不可新建。申办批准会在同一事务创建 `registered` 赛事及管理员，因此允许批准后、开赛前备墙；未批准的申请没有对应赛事，也无管理权限。
- 日额度以北京时间自然日计算，零点刷新。软删除释放存储额度，但保留创建记录，因此不恢复当天额度。
- 创建事务先取得个人账户或比赛范围的 PostgreSQL advisory transaction lock，再读取两项额度并写入，避免并发超额。

`duplicate_games(game_id, wall_id, ended_at)` 在开局时登记一条关联。`game_id` 与既有 `game_records.game_id` 一致；没有对 `game_records` 的外键，以支持先开局、后入库。牌谱入库与关联结束时间在同一事务内更新。牌墙 `ended_at` 表示最近一场已结束对局的时间；没有结束对局时为空，不是自动解除锁定时间。

## 牌墙来源与格式

`wall_type` 分为 `manual`（手动牌山）、`seed`（复现牌山）、`key`（密钥牌山）。每种类型都存储完整的有序牌值数组，并生成以 `dup_` 开头的 128 位随机密钥。种子生成使用带版本标识的 SHA-256 Fisher–Yates 算法；游戏读取最终数组，不依赖 JavaScript 与 Python 的伪随机算法一致。

`key` 类型由服务器用安全随机数生成内部种子。创建及管理接口不返回该类型的种子或牌序。`manual` 和 `seed` 类型的创建者管理接口可以返回牌序及已知种子；公共密钥查询返回元数据与对局列表。游戏服务内部加载 `seed` 和 `use_flowers`，终局将 `duplicate_key`、`duplicate_round_count`、`duplicate_round_tiles`（整场各局完整牌山）、兼容旧读者的 `duplicate_tiles`（首局）及 `duplicate_seed`（仅 seed/key 类型的整场种子）保存到受同一密钥保护的牌谱，解除锁定后随牌谱公开；锁定期间不向客户端发送这些内容，手动牌墙不显示无关的主种子。

牌值为整数：11–19 万、21–29 筒、31–39 条、41–47 东南西北中白发，各 4 张；51–58 春夏秋冬梅兰竹菊，各 1 张。提交时校验完整张数、牌值及每种牌的精确数量。

| 玩法 | 张数 |
| --- | ---: |
| 国标（`guobiao`，含花） | 144 |
| 国标（`guobiao`，`use_flowers: false`） | 136 |
| 国标蓝十改（`guobiao/lanshi`，无花） | 136 |

目录与创建接口只接受国标及蓝十改。创建面板默认无花并明确提交 `use_flowers: false`；接口省略此参数时保留旧版默认 `true`；蓝十改始终为 `false`，非布尔值拒绝。目录中的 `flower_options` 提供每个可选牌组的牌值数量，`supports_flower_toggle` 表示是否可切换。既有含花及蓝十改种子的生成结果保持不变；无花标准国标在同一版本算法中以 136 张牌生成并保存。其他麻将规则不能创建或使用新的复式密钥，赛事预设也会拒绝为非国标房间设置密钥。已有非国标牌墙和对局不删除，仍可管理原密钥并解除锁定；这些历史条目的显示不依赖当前可创建规则目录。

读取旧非国标赛事预设时，只去掉已停用的密钥字段和原复式日麻专用字段，保留原玩法、计时、起始分数及预设名称；依赖这些旧密钥的自动匹配会停用，避免静默改成普通对局。此读取过程不修改数据库原文档，新提交非国标密钥仍明确拒绝。

创建请求的 `round_count` 只允许整数 1、4、8、12、16，省略时为 1。`manual` 提交 `round_tiles: number[][]`，数组长度必须等于局数；每局独立校验完整牌组。旧客户端仅在单局时可以提交 `tiles`。数据库旧行默认 `round_count = 1`、`round_tiles = NULL`，读取时按 `[tiles]` 兼容，不重新生成旧牌山。

手动编辑可逐局选择四家的手牌与剩山。每局数组的四份按初始玩家编号 1–4 连续排列，每份 36 张（有花）或 34 张（无花）。本局庄家所在份额的开头 14 张为手牌，其余三家开头 13 张为手牌。每局换庄和第 5、9、13 局换位沿用国标流程；编辑器显示当局风位，原始玩家编号保持不变。

`seed` 输入一个整场种子，`key` 由服务端新建一个整场种子。首局保留原 `generateTiles(rule, seed, use_flowers)` 算法；第 N 局（N ≥ 2）先对 `duplicate-series-v1\0${seed}\0${N}` 做 SHA-256，取小写 hex 作为该局种子再生成牌山。增加局数不改变前面各局。所有最终牌序在创建时一次性保存，开局和换局不再生成牌山。

游戏按初始座位将牌墙连续等分为四份，默认座位 1 为东。每人初始发牌、庄家额外一张、后续摸牌与补牌都使用本人牌山。最后一张可以正常摸入并继续行动；轮到某玩家需要摸牌且本人牌山已空时才荒庄，荒庄或和牌结束当局后，继续使用下一局保存的牌山，达到密钥局数才结束整场；各局分数累计。国标普通房间及赛事预设支持 `use_flowers`；复式房间由数据库墙的值覆盖客户端或预设默认值。游戏服务会拒绝非国标玩法、牌组不匹配的国标子规则或所属比赛不匹配的墙。

新版牌谱记录 `duplicate_rules_version = 2`。Unity v2 回放按各自牌山尾部 2/1 位置补摸，旧版无版本牌谱保持原头摸逻辑，不改写旧谱。公开牌谱信息展示复式密钥、已解除锁定的种子及完整牌墙；手动牌墙不显示种子。

复式对局的四个玩家面板分别显示本人牌山的余牌数。开局、重连、每次动作和终局通过 `duplicate_remaining_tiles` 同步四个数量，数组按原始座位 0–3 排列；摸牌、补花和杠后补牌都从对应数量扣除，耗尽时显示 0。该字段只包含数量，不包含牌值或种子；普通对局省略。延迟发送的动作使用生成时的数量快照，避免提前显示后续摸牌的变化。复式终局会等待保护出牌补发完成，并排在同一玩家已有消息队列后发送，避免最终的 0 被旧动作覆盖。

## 锁与牌谱访问

新密钥默认锁定。创建者或所属比赛管理员可以解除锁定，此操作不可撤销，解除后不能再次锁定。接口在已有行锁事务内执行单向状态变更，重复解除锁定请求幂等且不改写首次 `unlocked_at`；已解除锁定的密钥请求设回 `is_unlocked: false` 返回 HTTP 409。锁定状态下重复提交 `false` 不改变状态。旧数据不会自动解除锁定，也不会根据日期自动公开。

查看及下载权限不因玩家参赛、拥有墙、赛事管理员或网站管理员身份而绕过锁。解除锁定后，该密钥对应的牌谱保持公开，创建者应在确认比赛结束、可以公开牌谱后执行。

所有 Web 原始牌谱路径使用同一个可见性检查，同时检查 `duplicate_games` 关联和 `record.game_title.duplicate_key`。已标记为复式但密钥不存在时拒绝访问；即使关联缺失，也不能通过 JSON 标题绕过检查。`is_duplicate`、`duplicate_seed` 或 `duplicate_tiles` 明确标记为复式但缺少密钥时，必须存在可验证且已解除锁定的关联才允许读取；Python 读取与原生转换分享采用相同保护。覆盖 2D/Unity 公开回放、个人单局与批量下载、赛事导出、后台原始 JSON、带原生元数据的转换分享及经典牌谱公开列表。批量导出在计入下载额度之前排除锁定记录，并在最终查询再次检查。牌谱响应禁止缓存。

所有锁定牌墙均不能删除，包括未进行任何对局的牌墙，删除请求返回 HTTP 409。解除锁定后软删除不删除历史对局或密钥，不改变公开状态与首次解除锁定时间。公开列表及详情包含 `created_at`、`unlocked_at`、`deleted_at`、`is_deleted`，并保留全部关联比赛与旧版仅通过标题关联的比赛。删除后的公开资料及牌谱仍可查询；游戏服务拒绝再用已删除墙开局。复式游戏不在玩家客户端自动保存本地牌谱。

## HTTP 接口

除目录和公开查询外，使用个人账户 Bearer token。成功响应统一 `{ success: true, data: ... }`，错误为 `{ success: false, message }`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/duplicate-walls/catalog` | 支持的玩法、牌值与数量、额度及 `round_counts` |
| `GET /api/duplicate-walls/mine?scope=personal` | 个人牌墙与当前额度 |
| `GET /api/duplicate-walls/mine?scope=event&event_id=...` | 有管理权限的比赛牌墙与共享额度 |
| `POST /api/duplicate-walls` | `{scope,event_id?,wall_type,rule,use_flowers?,name?,round_count?,round_tiles?,tiles?,seed?}`，返回 `{wall,quota}` |
| `PATCH /api/duplicate-walls/:id` | `{is_unlocked: true}` 不可撤销地解除锁定；重复请求幂等 |
| `DELETE /api/duplicate-walls/:id` | 仅可删除已解除锁定牌墙；软删除保留日额度与历史关联 |
| `GET /api/duplicate-walls/public?key=...` | 精确查找已解除锁定密钥；不传 key 返回最近解除锁定的 100 项 |
| `GET /api/duplicate-walls/public/:key` | 已解除锁定牌墙的元数据、结束时间及全部关联比赛 |

房间创建请求和管理员赛事预设通过 `duplicate_key` 使用已保存牌山。房间响应、房间列表、开局、重连和终局只发送 `is_duplicate`、`duplicate_wall_type`、`duplicate_round_count`，不发送密钥、种子或完整牌山。原始密钥保留在服务端房间状态供开局使用，终局写入受锁保护的牌谱；房间局数与花牌由密钥覆盖。客户端提交的牌序不能替换数据库牌墙。公开对局列表返回 `game_id`、`rule`、`event_id`、`event_name`、`created_at`、`ended_at` 及参赛者信息，不返回内部种子或墙数组。
