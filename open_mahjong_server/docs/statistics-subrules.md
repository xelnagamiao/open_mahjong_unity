# 麻将规则支持表

`server/database/statistics_rules.json` 是统计入口和 Excel 统计配置的共同来源，每个子规则一行。Excel 的主规则、子规则名称及排列顺序与创建房间面板一致，读取 `CreateRoomRuleTextConfigCatalog` 使用的 `RuleManifest`（优先 `LobbyName`）和 `LobbySubRules`；杭州麻将等拥有独立建房页面的规则各自作为主规则。

唯一维护版为 [`other/麻将规则支持表.xlsx`](../../other/麻将规则支持表.xlsx)，后续增删规则、调整数据均在此文件按现有格式维护，不另建日期版或改变列结构。固定十一列：**规则序号｜主规则｜首页显示名｜子规则名｜数据统计名｜规则标识｜是否提供匹配｜基础统计｜番种统计｜数据统计类型｜备注**。规则序号从 1 按子规则逐行连续编号，序号列公式随行位置计算；新增整行时延续公式。“是否提供匹配”只填“是／否”，基础统计和番种统计只填“有／无”；首页未显示的名称留空，没有统计入口的数据统计名留空。

Unity 普通和赛事创房面板通过“麻将规则支持表”按钮展示同一份数据，入口位于添加自定义规则按钮左侧。`RuleSupportTableBaker` 读取 Excel 的十一列内容并保存为固定 UI，构建场景时自动同步，校验每个单元格；运行时不维护另一份数据表。手动刷新使用 `Tools/Mahjong/Main Scene/Sync Mahjong Rule Support Table`。

每个子规则独立一行，使用原生 Excel 表格增删整行，保留筛选、下拉校验、居中、自动换行和主规则分组底色。标准规则身份列标金色，首页显示名标蓝；匹配的“是”、基础统计和番种统计的“有”分别标青、绿、紫。只冻结表头，不冻结列，不在子规则名和数据统计名之间添加竖线。备注默认留空，不逐条标注历史升级操作，不恢复已删去的默认注释。

- `sub_rule`：完整子规则标识，存储和查询的隔离边界。主规则名称不能代表多个子规则的合计。
- `key`：兼容客户端的统计入口标识；`stats_name` 是网页、Unity 下拉列表及 Excel 的“数据统计名”。
- `standard`：配表显式指定的标准规则，在入口和表格中高亮，不依赖标识后缀判断。
- `basic_stats`：是否接入基础统计。关闭时不显示统计入口；没有历史对局与没有接入统计是不同状态。
- `fan_stats` / `fan_key`：是否存储番种次数及对应字典。关闭时指标的 `fan_stats` 为 NULL，界面不显示番种区块。
- `player_count`：三人／四人的统计分母，不改变子规则隔离。
- `custom_modes`：全部支持的自定义／比赛局制；`ranked_modes`、`matchmaking` 由同步脚本从 `match/rating_rules.py` 的匹配队列生成。Excel 将两组局制完整列为 `[1/4] [1/4_rank]` 等，不依据已有数据删减。三人规则使用 `[1/3] [2/3] [3/3] [4/3]`，三人立直匹配使用 `[1/3_rank] [2/3_rank]`；前面的数字是圈数，后面的数字是人数，每圈三局，东风三局、半庄六局，立直连庄及延长战另计。历史 `/4_sanma` 和 `/3_sanma` 标识只作读取兼容，新配表和新对局统一使用 `/3`。虹雀前面的数字使用实际局数，自定义为 `[4/4] [8/4] [12/4] [16/4]`，Elo 匹配固定为 `[16/4_rank]`，界面直接显示“16局”。`/4` 保留现有统计协议形式，并非再将虹雀局数乘四。虹雀旧匹配 `4/4_rank` 实际同为16局，由发行版27升级修复；运行时只写规范编号，自定义4局独立保留。番种统计与匹配数量由配表决定，新增基础规则也必须经过同样的独立保存与查询链路。
- `home_header` / `home_label`：是否作为 Web 首页 Header 的快捷按钮及按钮短名。对应 Excel 的“首页显示名”列，显示项标蓝；留空表示不放入快捷栏，仍由 `basic_stats` 决定能否出现在全部规则下拉框中。当前快捷栏依次为国标、立直、青雀、古典、川麻(血战)、长沙，顺序沿用 JSON 配表顺序；Excel 按建房面板顺序排列，不改变快捷栏顺序。

增加规则或调整名称、统计能力时，先按 Excel 的列更新此配表，然后运行：

```text
python open_mahjong_server/scripts/sync_statistics_catalog.py
```

同步脚本生成 Web 配表和 Unity 统计目录；与 Python、Web、Unity 的改动一起发布。Excel 应从建房目录和同一份统计配表重新生成：主规则、子规则名称调整同步修改建房目录，数据统计名和统计能力调整同步修改 JSON，不能只改表格后让运行时继续使用旧配置。今后若计算口径变化需要修复历史数据，须另行提供可审计的离线升级步骤，先备份并在副本验证；不能恢复自动启动全量重算入口。

同步更新表格后运行格式与配表一致性校验；不一致时修正后再交付：

```text
python open_mahjong_server/scripts/validate_rule_support_table.py
```

## 存储与正常启动

`game_player_metrics` 的唯一键为 `(game_id,user_id)`，每行保留完整 `sub_rule` 和可选番种 JSON。九类保存入口将牌谱、参与者、近期记录、日麻摘要和逐局指标写入同一数据库事务；任一项失败则整体回滚，不返回保存成功的牌谱 ID。实时解析器位于 `database/record_metrics.py`。旧累计表只作兼容快照，`rule` 列存完整子规则，仅刷新当前对局涉及玩家，禁止增量混合累加或无范围全表重建。

游戏服启动通过 `database/statistics_schema.py` 初始化统计字段、索引和约束，重复执行不修改业务行或历史迁移标记；新库无需运行历史重算即可保存对局。游客本人、机器人整桌沿用统计排除口径。

完整子规则身份优先取牌谱的 `game_title`，已知旧别名按原谱配置解析，未知子规则不得并入标准规则。极早期牌谱没有子规则字段时，才兼容同主规则的旧索引。

发行版27历史修复工具已从常规源码退役，原文件与验证记录保存在本机 Git 忽略的 `.om_workspace/` 归档中。数据库内原始牌谱、评级、备份及完成标记保留；普通启动不会再修正参与者索引或覆盖历史指标。

已升级数据库保留 `subrule_statistics_rebuild_v4_hongque_modes` 作为历史审计标记，不再作为启动触发器。尚未完成发行版27数据升级的旧库必须先单独备份、修复和验证，不能把正常结构初始化视作历史数据已经对齐。正常启动仅补齐已结束统计日的聚合及近期记录缓存失败项；新对局保存成功即能查询个人基础和番种统计，平台仍按北京时间 04:00 发布已结束统计日。

国标、日麻、青雀和古典沿用原字段，其他有番种规则保存结算器的规范中文名称，Web 与 Unity 同时支持已知字典和实际计数中的新增名称。`*N`／`×N` 按达成数量累计，虹雀旧 `|N` 番值不当次数；敲麻的可配置“（N番）”去除，港麻“正字（门风）”等名称保留。长沙鸟牌、骰子、付款倍数和台湾连庄附加台数不充当番种。

长沙起手胡另存每回合的 `initial_hu_events`，不冒充结束回合的和牌事件。旧牌谱若未记录这一事件，无法从最终分数无歧义恢复其番种，回填只统计原始牌谱实际留存的证据；新牌谱直接完整记录。

无独立番种统计的规则只隐藏番种出现次数，基础统计中的平均和番／平均铳番仍属于基础指标。

## 验证

`tests/database/test_subrule_statistics.py` 使用独立临时 PostgreSQL schema，覆盖结构初始化幂等与数据保留、实时重复写入、旧累计表按玩家限定范围、子规则隔离和原谱身份解析。
Web 的 `subruleStatistics.integration.test.js` 逐一验证全部可显示入口的名称、基础数据、番种开关及首页与个人统计一致。
`test_subrule_realtime.py` 覆盖配表全部子规则的番种能力、换位和三人席位、计数后缀、全部支持统计的子规则的真实保存入口、九类保存入口中途失败及重试，以及重复正常启动不改写逐局指标。虹雀测试验证各局数独立保存、查询和按日聚合。Web 集成验证新番种不被旧字典过滤、同主规则子规则隔离、虹雀各手数独立筛选。
