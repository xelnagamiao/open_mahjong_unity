# 大厅组队、好友邀请与川麻双打排位

当前开放双人组队。大厅队伍与牌局内队伍分别维护：组队不会创建房间，进入匹配后由队列策略分配牌局座次。

## 玩家流程

- 组队面板位于匹配页面内，仅选择川麻「血战 2V2」时显示，展示成员、队均 Elo、匹配计时和范围。队长头像始终显示皇冠，独自一人时也显示。
- 队长通过通用好友面板邀请在线的双向好友；接受后成为队员。组满两人后，任意成员均可点击 Elo 场次或「开始匹配」入队，无需额外准备。
- 开始、取消组队匹配时，服务端向整队发送 `party/notice`，双方客户端通过顶部 tips 展示操作者和动作。重复的开始或取消请求不会重复通知。
- 未组队时点击双打匹配框只提示「进入2v2匹配需要邀请好友组队」，不自动打开邀请面板。邀请面板的组队文案不绑定具体麻将规则。
- 组队期间点击单人匹配场次时提示「组队期间无法进行单人匹配」。
- 任一成员可以取消整队匹配；离队也会取消整队匹配。队长可以移出成员或转让队长。已提交匹配的阵容在对局结束前锁定。
- 房间的复制邀请弹窗增加「邀请好友」，与组队共用 `FriendInvitePanel`；房间邀请始终使用房间实例 ID，接受后进入既有链接解析、密码验证和入房流程。
- 邀请有效期 60 秒。未提交匹配时断线会取消整队匹配，保留成员 60 秒以便重连，超时后移除并按需转让队长。

## 服务端协议

所有请求经已登录的游戏 WebSocket 发送，以当前连接的用户身份鉴权。`party/state` 为权威快照，客户端使用队伍 ID 和 `revision` 应用更新。

| 请求 | 关键字段 | 行为 |
| --- | --- | --- |
| `party/get` | 无 | 获取自己的队伍状态 |
| `party/invite` | `target_user_id`, `kind` | 发送 `party` 或 `room` 邀请；房间邀请另传 `room_id`, `room_instance_id` |
| `party/respond` | `invite_id`, `accept` | 接受或拒绝发给自己的邀请 |
| `party/revoke` | `invite_id` | 撤销自己发送的邀请 |
| `party/ready` | `ready` | 保留的准备状态接口，当前双打入队不要求准备 |
| `party/queue` | 无 | 任意成员发起双人队伍匹配 |
| `party/cancel` | 无 | 取消整队匹配并清除准备状态 |
| `party/leave` | 无 | 离开队伍 |
| `party/kick` / `party/transfer` | `target_user_id` | 队长移出成员或转让队长 |

通知使用 `party/incoming`、`party/invite_closed`、`party/state`。匹配状态沿用现有 `my_queues`、`match_revision` 和 `match_committed` 字段；入局沿用现有匹配倒计时和游戏状态协议。

## 双打匹配与评分

- 队列 ID：`sichuan_doubles_elo_banzhuang`；独立评分池：`sichuan_doubles`；算法：`team_elo_mean_2400_v1`。
- 使用现有 `sichuan/doubles` 血战双打规则，半庄 8 副，两队交错入座，队友对坐。
- 队伍强度取两名队员双打 Elo 的均值，队内分差不得超过 500。
- 对手均分范围按等待时间扩大：30 秒内 ±100，60 秒内 ±200，120 秒内 ±350，之后 ±500；必须同时满足两支队伍各自的范围。
- 初始 Elo 为 1500。预期得分 `E = 1 / (1 + 10^((对手队均分 - 本队均分) / 2400))`，每名队员变化为 `32 × (S - E)`。
- `S` 由服务端最终团队比赛分决定，胜为 1，平为 0.5，负为 0。同队两人涨跌相同，双方严格零和，换队友保留个人双打 Elo。
- 评分写入沿用现有数据库事务和幂等结算，不修改其他规则的排位分。

## 后续扩展

队伍使用成员数组、`capacity`、队长和准备集合；Unity 组队栏预制了 5 个成员槽。后续开放 4 人、5 人队伍时，需要配置容量并增加对应队列策略，当前双打队列仍严格要求 2 人。当前队伍和未处理邀请保存在服务端内存中，服务重启后重新组队；Elo 保存在数据库中。

Unity 场景入口为 `Assets/Scenes/MainScene.unity`。`PartyUiBaker` 增量生成组队栏、共用邀请面板和双打匹配入口，并验证项目绘制层约束。`RankedRulesUiBaker` 和 `RoomInviteUiBaker` 已接入相应的重新生成流程。

自动化覆盖位于 `server/match/test_party.py`、`server/database/test_rule_ratings.py`，包括权限、邀请失效、队伍并发、断线、整队匹配、真实游戏状态和团队 Elo 结算。Windows 构建、日志和本机隔离联调记录位于工作区忽略目录 `.om_workspace/party-2v2/`。
