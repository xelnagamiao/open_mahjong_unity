# 三人立直段位匹配

三人立直使用独立评分池 `riichi_sanma`，从 10 级、0 PT 开始。四人立直的段位和 PT 继续单独保存。第一名加分、第二名不变、第三名扣分，仅按最终顺位计算，不使用终局点数或四人立直的比赛分公式。

| 场次 | 东风战：第一／第二／第三 | 半庄战：第一／第二／第三 |
| --- | --- | --- |
| 初级 | +30／0／−30 PT | +45／0／−45 PT |
| 中级 | +50／0／−50 PT | +75／0／−75 PT |
| 高级 | +70／0／−70 PT | +105／0／−105 PT |

数值参考[天凤官方说明的三人段位战](https://tenhou.net/man/index.html#DAN)中头名奖励及东南战系数；本平台采用对称的第三名扣分，简化为上表。同点按起始座次排序，东、南、西依次优先。

升降段使用平台既有 10 级至十段门槛。达到升段门槛时升段；允许掉段的段位在 PT 小于 0 时掉段。低段位无法掉段时余额最低为 0，因此记录中的名义扣分可能与余额差值不同。十段沿用永久称号规则，固定 100／100 PT，每局变动为 0。新增评分池不重算原四人评分，也不追溯自定义三人对局。

## 匹配与玩法

开放六个队列：`riichi_sanma_{beginner|intermediate|advanced}_{dongfeng|banzhuang}`。按入队顺序凑齐三人即开局。三人、四人可以同时排队，仍共用最多四个等待场次的上限；任意一桌匹配成功后立即退出该玩家其他所有队列，直到本局清理才解除匹配锁。

初级场无段位门槛；中级场允许三人立直 1 级至六段；高级场允许四段及以上。特许资格沿用已有机制，七段及以上仍不能进入中级场。判断读取三人评分池。初级场提供枚数提示，中高级场无番数和枚数提示；中级场计时为 20+8，其他为 20+5。

游戏使用既有 `sanma_tenhou` 预设：三人、35000 点、万子移除二至八万、筒索各一张赤五、拔北和自摸损。完整玩法见[三人立直规则](riichi-sanma.md)。自定义房间不结算段位。

## 数据和客户端契约

- 评分、排行榜及结算规则为 `riichi_sanma`，算法标识为 `riichi_sanma_place_pt_v1`。
- 实际对局和牌谱继续使用 `rule=riichi`、`sub_rule=riichi/sanma`，局制统计为 `1/4_sanma_rank` 或 `2/4_sanma_rank`。
- 数据库迁移为新增评分池许可，不覆盖已有评分。三人结算要求三名不同的注册玩家和有效顺位；与子规则、人数不一致的请求在写入前拒绝。
- 整桌原子提交，按对局 ID 防止重复结算；失败时整桌回滚，并发重复请求只计一次。
- Unity 的首页评分切换、匹配规则页、场次说明、玩家资料、独立排行榜和段位结算均包含三人立直。统计、役种及近期顺位走势按三人、四人分开读取，三人走势只显示三个顺位。

## 验证入口

服务端测试：`server/match/test_sanma_rank_calculator.py`、`server/match/test_sanma_ranked_match.py`、`server/database/test_sanma_ratings.py`，并由通用匹配、真实 WebSocket 和数据库测试覆盖全部队列。真实数据库测试仅在提供 `RATING_TEST_DATABASE_URL` 时运行，使用自动清理的临时 schema。

Unity 的 `RiichiSanmaRankValidation.Run()` 检查评分契约与已保存的主场景引用；`RiichiSanmaRankClientValidation` 仅在开发构建显式传入 `--verify-sanma-rank <报告目录> <loopback地址> <测试UID>` 时启动，用于真实三客户端匹配、重连和结算检查。正常启动不运行验证。

`Tools/Mahjong/Main Scene/Add Three Player Riichi Ranked UI` 在非播放状态下增量维护主场景入口、资料按钮、排行榜选项和规则说明。不得手工修改场景 YAML。
