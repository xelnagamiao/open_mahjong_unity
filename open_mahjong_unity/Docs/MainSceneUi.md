# 主场景 UI

固定页面在 `Assets/Scenes/MainScene.unity` 中编辑。创房示例工程已退出使用。

段位匹配页面的对象位置与交互设置见 [段位匹配面板编辑说明](RankedMatchSceneEditing.md)。

四规则段位／Elo、数据页规则下拉、玩家评分和数据库迁移见 [四规则段位与 Elo 匹配](RankedRules.md)。固定结构通过 `Bake Ranked Rules UI` 保存到主场景和排行榜预制体，沿用原 MainCanvas 与 Header。

- 普通创房、赛事创房各自保存国标/日麻预设、台湾馆规、台表和日麻高级设置。日麻高级设置列数是 `CreateRoomDetailsLayout` 的序列化字段。
- 两处创房面板的“我想添加自己的麻将规则”左侧均提供“麻将规则支持表”。十一列随窗口宽度自动分配，长内容换行、行高自动增长，固定表头且只纵向滚动；关闭或点击遮罩返回创房草稿。表格单独使用 64 点采样的静态 SDF 字体，字号、列边界和滚动位置按输出像素对齐。表格按子规则连续编号，内容唯一来源为 `other/麻将规则支持表.xlsx`。通过 `Tools/Mahjong/Main Scene/Sync Mahjong Rule Support Table` 更新场景，固定 UI 烘焙和构建时也会自动同步内容及所需字形；玩家端无需读取 Excel。
- 房间面板的机器人速度下拉保存于底部 `BotSpeedRow`，在开始按钮左侧、有机器人时显示；四档为极快、快速、中等、慢速，默认快速。空座位的添加按钮由 `PlayerRoomPanel.Baking.cs` 烘焙，入座后隐藏。房主在开局前调整，所有客户端以房间广播值为准。`RoomPanel.Baking.cs` 也固定下拉弹出区尺寸，避免继承创房模板的空选项高度。
- 鸣牌保护在普通／赛事创建房间面板中选择，排列在“战术鸣牌”之后，使用与其他创房选项一致的黑色文字。国标、青雀、长沙、四川（含血流）和中庸（含南雀）默认开启，立直默认关闭；其他规则隐藏。建房后的房间配置只读显示实际“鸣牌保护：开／关”，底栏不再提供修改入口。添加任意机器人后自动关闭，移除全部机器人后恢复创房选择；机器人速度和战术鸣牌开关独立保留。
- 国标首次进入及切换规则时应用初级场，日麻应用雀魂规和东南战；同一规则下重新打开面板保留草稿。恢复默认设置须确认，并保留当前子规则。
- 底部配置提示及恢复按钮直接保存在两处创房面板中。`CreateRoomHelpTrigger` 的提示与所属面板由编辑器烘焙，鼠标悬停、点击和键盘选中时更新底部文本。
- 创房时通过已烘焙的 `ChatPanel/CanvasGroup` 隐藏聊天并屏蔽输入，消息处理保持运行；离开后恢复原有主播模式对应的显示状态。
- 观战整页直接保存在主场景；`SpectatoItem.prefab` 仍用于动态观战条目。房间、牌谱等列表条目预制体保持原用途。
- 仓库面板保存在 `OverlayCanvas/StorePanel`，通过主菜单侧栏“背包”按钮打开。固定布局及入口事件由 `InventoryPanel.Baking.cs` 烘焙。左侧竖排标签为背包/头衔/角色/装扮，每次正常打开默认进入背包，无“全部”标签。面板横向加宽，中间为每行四个、接近方形的物品卡片网格，右侧为独立的预览、详情及操作区；沿用深蓝配色，使用简单图标、数量标记和清晰的选中态。详情保留物品效果或头衔自身描述，省去重复的操作说明。背包目前收纳改名卡，顶部显示可用改名次数，右侧“点击改名”经确认后在浏览器打开个人账户面板；使用数量支持输入及加减按钮，范围为 1 至持有数量（单次最多 100）。角色及装扮无库存时显示空状态。头衔只显示默认“暂无头衔”和当前玩家已获授的头衔，佩戴后同步大厅、资料与对局。
- 通知正文滚动区域、番数/枚数提示标签保存在各自可复用预制体中；复式余牌标签和听牌提示边框保存在主场景。
- 国标、立直、青雀、虹雀、川麻血战对局／牌谱点击“规则书”直接打开对应番表。顶部为“番表”、五种规则下拉框及“打开完整说明书”按钮，切换规则同时更新分类、内容和说明书链接；返回房间原规则时保留子规则说明书地址，关闭番表返回牌桌。其他规则及川麻血流、双打等子规则保留原说明入口。五套资料分别包含 82／38／89／37／11 条，青雀按书载十类与权重展示。定义、不计项和牌例条件取自随附规则书，来源详见 [FanCatalogSources.md](FanCatalogSources.md)。界面省去来源副标题、通用“牌型示例”和底部注释。固定遮罩、页签、滚动区和条目模板保存在主场景，运行时复用条目。内容位于 `Assets/Resources/*FanCatalog.json`，普通牌例使用 m/p/s/z/f 分组记法，虹雀使用逗号分隔的 AX1 等彩色牌代码。Web 仅同步国标 JSON 到 `client/src/constants/guobiaoFanTable.json`，运行 `node --test tests/guobiaoFanTable.test.mjs` 检查一致性及资源。通过 `Tools/Mahjong/Main Scene/Bake Guobiao Fan Table` 定点更新界面；`GuobiaoFanCatalogValidation.Run()` 使用正式计番器核对国标番值、牌例和牌面资源。

`Tools/Mahjong/Main Scene/Bake Fixed UI` 只在编辑模式下补齐固定控件及创房样式，并同步规则目录的下拉文案；保存场景后生效。`Validate Fixed UI` 检查引用、完整配置、文案与布局。构建时也会验证，缺失时直接报错，不由 Player 临时克隆页面掩盖问题。

`CreatePanel.Baking.cs` 及其他 `UNITY_EDITOR` 烘焙方法是维护工具，不进入 Player。运行时保留规则驱动的显示/禁用、分辨率适配、滚动、动画、动态列表及可同时出现的通知弹窗。
