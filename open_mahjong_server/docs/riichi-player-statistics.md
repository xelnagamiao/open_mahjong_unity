# 日麻玩家统计设计

## 原设计与缺口

原表 `riichi_history_stats` 按用户、规则、局制累计对局数、小局数、和牌、自摸、放铳、副露、番数、和巡和顺位；`riichi_fan_stats` 累计和牌役种。原定义见 `server/database/riichi/db_design.md`。

这套设计没有成立立直局数、立直巡目和立直失败结果。役种表中的“立直”只表示和牌时带有立直役，不能用来计算立直率。旧 Web 日麻 `fanField` 为 `null`，没有役种统计入口；Git 历史 `ca1fe167`（2026-07-31）已存在此配置，不能归因于上次更新。日期筛选只能提供顺位，详细指标需要下载分析；本地分析器原先又使用国标番种映射和巡目，漏掉日麻流局、立直棒与起始点数。

实现采用原有对局记录和查询入口，新增 `riichi_player_game_stats` 每玩家每场摘要。新对局与牌谱同事务保存；启动维护增量重建历史，按 `(game_id,user_id)` 覆盖写入，重试不会重复累加。旧累计表保留。摘要有版本号，修正口径后可升级版本重新生成。

## 参考与展示分层

参考 [雀魂成績界面资料与截图（Game8，2025-11-21 更新）](https://game8.jp/jantama/632791)，基础资料卡主要使用顺位率、被飞率、对局数、平均顺位、平均和牌打点、和牌率、自摸占和牌、放铳率、副露率和立直率。该资料不是雀魂官方统计口径规范，不据此推定其内部计算方式。

[天凤官方战绩定义](https://tenhou.net/man/)列出对局数、平均得点、平均顺位、各顺位率、被飞率、和牌率、放铳率、副露率和立直率。[天凤牌谱解析](https://cdn.tenhou.net/7/)另列立直、默听、副露的和牌／放铳／流局，以及副露次数、巡目向听等拆分指标。项目据此将一般战绩与条件分析分开。

| 入口 | 展示项目 |
| --- | --- |
| Unity 玩家资料、Web 玩家数据、标准分析 | 16 项基础指标：总对局、总回合、平均顺位、局均点（第 4 项）、四个顺位率、和牌率、自摸率、放铳率、副露率、被飞率、立直率、平均和了打点、平均和了巡目 |
| 数据站 → 牌谱分析 → 高级分析（日麻） | 基础指标之外，分为立直分析、副露与门清、流局与失点、点数与和牌四组；显示平均立直巡目、立直后和牌／放铳率、副露后和牌率、默听和牌占比、流局率、荒牌流局听牌率、被自摸率、平均放铳失点、平均终局点数和平均和了番数 |

高级分析显示当前已下载牌谱的样本数、成立立直次数、副露小局数、和牌次数、荒牌流局次数等分母背景。无条件样本时对应比率和均值显示“—”。默听和牌占比的分母为全部和牌，不能解释成“默听后的和牌率”。后端仍保存全部原始计数，展示分层不改变统计事实或存储口径。

## 已实现的指标

所有个人比率都以同一玩家、同一日期和场次筛选的原始计数计算，合计后再计算比率。每个带 `end` 的小局计一次，连庄也计一局；未结束的小局不进入行为指标分母。日期为起始日 00:00 至结束日次日 00:00 的半开区间。

| 指标 | 口径 |
| --- | --- |
| 对局数、平均顺位、各顺位率 | 按实际保存的结算顺位；顺位率分母为有有效顺位的场数 |
| 和牌率、放铳率 | 和牌局数或放铳局数 / 已结束小局数 |
| 自摸率 | 自摸次数 / 和牌次数，沿用原有公式 |
| 被自摸率 | 对手自摸且本家实际失点的小局数 / 已结束小局数 |
| 立直率 | 成功支付立直棒的局数 / 已结束小局数；双立直按一次；宣言牌被荣和不计成立 |
| 平均立直巡目 | 成立立直时本家的第几次弃牌；被鸣走的弃牌仍计数 |
| 立直后和牌率、立直后放铳率 | 对应结果局数 / 成立立直局数 |
| 副露率、副露后和牌率 | 明副露局数 / 小局数；明副露且和牌局数 / 明副露局数；暗杠保持门清 |
| 默听和牌占比 | 门清且未成立立直的和牌数 / 和牌数，含门清自摸 |
| 流局率 | 荒牌或途中流局的小局数 / 已结束小局数 |
| 荒牌流局听牌率 | 荒牌流局本家听牌局数 / 荒牌流局局数，排除途中流局 |
| 平均和了打点 | 和牌实际获得点数的平均，包含本场和供托 |
| 平均放铳失点 | 实际放铳支付点数 / 放铳局数；一炮多响计一局，累加各家失点；包牌责任支付不当作放铳 |
| 平均和了番数、巡目 | 番数与点数分开；和牌巡目按本家待和巡目计算，详见下节 |
| 局均点 | 原累计净得点 / 玩家参赛场数；已知起始分时，采用实际终局点数减起始点数，缺失时使用已解析的事件收支。基础指标保留已算出的数值，零分母显示 0 |
| 平均终局点数、被飞率 | 有终局点数的场次计算；终局小于 0 记被飞，0 点不记 |
| 役种统计 | 次数及占和牌比例；宝牌、赤宝牌、里宝牌显示总枚数与每和牌平均枚数 |

基本的和牌／放铳／副露口径参考 [天凤官方说明](https://tenhou.net/man/)，特别是暗杠不计副露、一炮多响仅一个放铳者、包牌支付者不算放铳。本项目允许错和后继续游戏、特殊起始点数等配置，上表明确记录了项目自己的统计约定。

## 个人巡目的定义与验证

[天凤官方牌谱解析](https://cdn.tenhou.net/7/)声明巡目按各玩家分别计算，但公开说明没有完整规定荣和、岭上补牌的加巡细节。检查的[雀魂牌谱屋公开解析代码](https://github.com/SAPikachu/amae-koromo-scripts/blob/master/index.js)则使用“全桌累计弃牌数 / 人数 + 1”计算立直及和牌巡数；它是第三方统计口径，不能当成雀魂官方定义。这两种口径不能直接比较，也不能用牌谱播放器的全桌动作序号代替个人统计巡目。

本项目沿用已实现的个人弃牌口径，并明确其含义为**待和巡目**：

- 每小局为每位玩家独立累计所有执行过的弃牌，包含后来被吃碰杠走的牌；不使用屏幕牌河当前剩余张数。
- 和牌巡目为和牌时本家历史弃牌数 + 1，自摸和荣和都按此约定。已有 5 次弃牌且尚未下一次摸牌时荣和，计 6；尚未弃牌时和牌计 1。这是待和区间的编号，不等于已经执行的摸牌次数。
- 吃碰后弃牌计入本家次数，被跳过摸打的玩家不增加次数。暗杠、加杠与岭上补牌本身不增加弃牌序号；同一次弃牌前连续杠仍处于同一待和巡目。
- 立直巡目使用宣言弃牌自身的序号（宣言弃牌已计入，故不再 +1）。只有成功支付立直棒的事件进入成立立直统计，即使先执行了吃碰，延迟支付也不改变宣言者的序号。
- 每个连庄小局重新计数，按小局 `seats` 将原始玩家索引映射到当前座位。一炮多响各和牌者分别取自己的次数。
- 平均和牌巡目 = 所有有效和牌的巡目总和 / 和牌次数；跨局、跨场、跨模式先合计分子和分母，不能直接平均各场均值。流局、错和、未结束小局不进入和牌样本。

旧实时和牌累计使用 `self.xunmu`，且该值在庄家切牌后递增，既不能表示所有玩家的个人巡目，也可能将子家首巡和牌计成第二巡；旧 `player.riichi_turn` 也使用此值。现在两者改为本家 `discard_origin_tiles` 的计数，与 Python 摘要和 Web 本地分析一致。全桌 `xunmu` 的对局进程用途保留。

摘要版本已升级为 3。Python 首次启动新版时，在接收对局前执行 `riichi_player_statistics_v3` 迁移：从所有现存日麻牌谱全量覆盖逐玩家摘要（包括已经存在的摘要），修复巡目、立直、和牌、副露、点数、顺位及役种计数。按原累计表的用户和模式汇总，现存牌谱场数能覆盖旧累计场数时，同时覆盖基础累计表及役种表；牌谱不足的分组保留旧累计，并将用户、模式和缺口记入迁移结果，不能从旧总和猜测缺失对局。旧三麻 `/3` 模式在可覆盖时归并为 `/4_sanma`；已重建的规范行不会再重复累加别名数据。Web 本地分析同时按三／四人席位处理牌谱，并保持拔北补牌的行动者。

场次明细 `game_player_metrics` 的日麻计数同步覆盖为新摘要，并重建受影响统计日的日麻 `scene_daily_stats`；其他规则的数据保留。后续缺失场次明细的回填也使用日麻分析器，避免重新写入通用巡目。

`riichi_stats_rebuild_backups` 按旧行保存摘要、基础累计、役种、日麻场次明细及受影响日汇总的修复前快照；`riichi_stats_rebuild_migrations` 保存版本、修复数量、未覆盖分组和完成时间。备份、修复及完成标记同事务提交，异常全部回滚，下次启动重试；数据库事务级锁防止多个进程重复重建，表锁防止重建期间新增结算混入。迁移完成后的启动直接跳过全量重建，原启动维护继续补缺失或过期摘要，不重复累加。Python 与 Node 查询只使用版本 3 的摘要。

缺失牌谱的旧累计巡目无法从总和恢复到个人口径。若未来选择“已执行的摸牌次数”或其他外部平台兼容口径，需要单独定义补牌、副露与首巡荣和，再升级版本从牌谱重建，不能仅修改显示名称。

## 展示与筛选

- Web 首页：快捷入口依次为国标、立直、青雀、古典、川麻(血战)、长沙，桌面标签区沿用半栏宽度，在右侧下拉之前留白；其他玩法（包括川麻(血流换三)）通过“全部规则”下拉选择。数据选择器使用红中麻将、自由模式、古典麻将、中庸麻将、立直(三人)、国标(三人)等完整名称。国标、立直四麻和三麻默认选初级场；青雀、川麻各玩法默认选段位场，其他规则默认选自定义；每次切换规则重新应用默认场次。日麻按初级／中级／高级、自定义、比赛场筛选，去掉“全部段位”选项和底部口径注释；三麻兼容旧 `/3` 局制并与四麻隔离。总对局显示去重后的实际桌数，总回合显示参与者的有效小局累计；合计行为分子与分母后计算个人平均，不将四家的和牌率相加。局均点始终位于第 4 项。基础指标展示可计算值，不因明细缺失而隐藏。三麻不显示四位率。川麻血流、血流换三和血战按子规则独立统计；多次和牌、放铳使用全桌局均次数。广东麻将与广东麻将（推倒和）按子规则分别统计，三人国标独立统计，南雀放在下拉列表末尾。
- Web 玩家数据页：日期、匹配／自定义／比赛场、具体场次和局制筛选使用同一批摘要，保留历史自定义长局；不用下载完整牌谱即可获得基础指标，亦不消耗牌谱下载配额。条件统计从普通表移至高级分析。公式通过指标提示展示。
- Web 本地牌谱分析：标准分析使用基础指标；高级分析支持国标和日麻，日麻按上表分组，不使用国标听牌、凑番和或安定段位模型。两者使用同口径日麻分析器，修正立直棒、流局、门清、役种、点数与顺位。新谱带 `game_title.riichi_points` 时优先使用真实终局点数；旧谱按起始点数和事件收支重建，同分按原始席位排序。
- Unity 玩家资料：沿用可展开局制明细，匹配和自定义分别统计。天梯固定显示国标、立直、青雀、川麻血战，另提供其他匹配规则下拉列表；自定义下拉加入三人国标、三人日麻、两种广东麻将，南雀在最后。`data/get_rule_stats` 按玩法、子规则、人数和自定义场读取同一批逐玩家明细，并回显请求标识；三麻日麻仍返回 `riichi_details` 和役种计数。
- 摘要未完成或无法解析时，基础指标保留已知计数并显示计算结果；高级条件分析在条件分母为零或明细不可用时显示“—”。旧累计表仍保留，但不把缺失牌谱的累计计数混入特色指标的分母。已删除记录无法重建成立立直等行为。含机器人对局仍遵守原有“不保存云牌谱／不计云统计”规则。

自定义场现已写入 `game_player_metrics`。首次 Python 启动执行 `home_rule_statistics_v1`，不受日聚合日期游标限制，追溯所有现存牌谱补齐缺失明细。旧 `jiandan`／`nanque` 规则别名先保存原行快照，再统一为 `zhongyong/nanque`；内部旧累计表名和兼容接口保留。广东的 `mil2023` 与 `tuidao_mil2024` 子规则保存为独立维度。上海的 `qiaoma`（敲麻）与 `qinghunpeng`（清混碰）也独立选择、存储和查询，旧上海记录缺少子规则时沿用当时默认的敲麻。展示地区玩法时使用“长沙麻将”“台湾麻将”等完整名称；`hongque` 的名称为“虹雀”。南雀延迟到局末的支付只计入净得分，和了次数从原和了动作计一次，避免零支付动作漏记或结算重复计数。

## 后续扩展边界

本次交付提供基础战绩，以及用于高级分析的立直／副露条件结果、流局与失点统计。追立直／先制立直、立直收支、对立直押降、良形／愚形、听牌速度等更深分析需要明确对手宣言时点、等待形、策略状态及额外样本口径；它们不从现有汇总猜测，也未混入本次指标。三麻已按实际三人席位解析，并使用独立模式汇总；与四麻对比时仍需保持规则、样本和分母一致。

## 验证

Python 与浏览器分析器共享 `server/database/riichi/stats_cases.json` 契约样例，覆盖成立立直失败、宣言牌未成立、一炮多响、暗杠、座位变化、荒牌／途中流局、未结束局、特殊起始分、包牌责任支付。数据库测试在独立临时 schema／临时表运行，验证各场次隔离、日期边界、逐玩家数据和重复回填。前端测试另验证基础指标不包含条件统计、高级分析使用正确样本及无样本状态。构建与本机验证记录放 Git 忽略的 `.om_workspace/20261004-riichi-stats/`。
